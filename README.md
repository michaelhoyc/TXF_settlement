# TXF Settlement Zone | 台指期結算區間

台指期每月結算區間圖。日 K 用來期交所每日行情的**指定契約月份**（一般交易時段），官方最後結算價用來期交所公布的數值，並把圖推播到 Telegram。

Shioaji 只在期交所缺日、而且該月份還沒到期時，用單月合約補資料。不使用 `TXFR1` 連續近月來組日 K。

---

## 圖上各條線是什麼

| 項目 | 意義 |
|------|------|
| K 棒、成交量 | 當日近月契約的**日盤**（08:45–13:45）。結算日用的是**到期月份**，不是新月份 |
| 色帶（OC） | 該到期月份結算日的日盤開盤與收盤。這不是最後結算價 |
| 較粗的水平線（FSP） | 期交所官方最後結算價：結算日現貨指數收盤前 30 分鐘的平均 |
| 標籤 | `M/D`、`FSP 價格`（取不到則 `FSP N/A`）、`OC` |
| 黃線 ContractAvg | 每個契約期間，日典型價 `(開+高+低+收)/4` 的**成交量加權**累積均價。不是主力成本，也不是逐筆 VWAP |
| 顏色 | 最新結算日固定最深；不足 8 個也不會改成整組淺色。超過 8 個時，更舊的區間共用最淺色 |
| 右側數字 | 只標最新一筆：`FSP`，以及開收盤較高、較低的兩個價 |

第一個結算日之前，若沒有更早的結算錨點，黃線不畫，並在圖上與日誌標成不可用。正常執行會多取前一次結算當錨點，所以最舊一段會從該契約的下一個交易日開始，圖會比「結算日前 10 個日曆天」再往前約一個契約。

---

## 結算日

台指期月契約的最後結算日是**到期月份第三個星期三**。那天不是交易日時，順延到**下一個交易日**（例如 2026-02-18 農曆春節，實際結算日是 2026-02-23，契約月份仍是 `202602`）。

交易日曆順序：

1. FinMind `TaiwanStockTradingDate`（不需會員；有 `FINMIND_TOKEN` 會一併帶上）
2. 失敗時用 `data/twse_trading_days.json`（2018-01-02～2026-12-31 的快照）
3. 日期超出這份快照時，才把週一到週五當成交易日，並在日誌與 Telegram 警告：國定假日可能沒被排除

結算日必須剛好對到那根日 K。對不到就寫警告並略過該價格帶，不會再往後猜 0～2 個日曆天。

---

## 換月

近月在結算日的日盤仍是到期月份；期交所日報把「前一晚夜盤 + 當日日盤」記在同一個交易日，所以結算日的夜盤也算到期月份。下一個交易日（含它的夜盤，也就是結算日 15:00 之後）才換下個月份。

`TXFR1` 會在結算日更換 `target_code`，1 分 K 可能把新舊月份接在同一天。已到期的單月代碼，Shioaji 也查不到。因此日 K 主來源是期交所每日行情裡的 `TX` 月契約（`YYYYMM`），週契約與價差列會丟掉。

---

## 官方最後結算價

1. 期交所「指數期貨最後結算價」頁（`futIndxFSP`，只取 TX 月契約）
2. 若設定 `FINMIND_TOKEN` 且帳號為 Backer 以上，缺的日期再向 FinMind `TaiwanFuturesFinalSettlementPrice` 補
3. 還是沒有：該日不畫 FSP 線，標籤為 `FSP N/A`，日誌與 Telegram 會說明。**不會**用日盤開收盤，也不會用每日行情的「結算價」欄代替（到期當日該欄常是 0，而且它是每日結算價，不是最後結算價）

---

## 黃線（VWAP）

每個契約從「前一次結算日的下一個交易日」累積到自己的結算日（含）。

- 預設只加權日盤典型價
- `python settlement.py 8 --include-night` 會把同一交易日的夜盤典型價依成交量一起加權
- 成交量柱仍是日盤，避免和 K 棒對不上
- 這是日 K 典型價的成交量加權，不是逐筆成交的 VWAP

## 安裝與測試

- Python 3.9+

```bash
pip install -r requirements.txt
pytest
```

沒有 Shioaji、期交所或 Telegram 憑證也可以跑測試。測試只覆蓋結算日、假日順延、指定月份銜接、VWAP、文字與一張用假資料畫出的圖。

## 環境設定

在專案目錄建立 `.env`（不要提交）：

```env
API_KEY=your_sinopac_api_key
SECRET_KEY=your_sinopac_secret_key
TG_TOKEN=your_telegram_bot_token
TG_CHAT_ID=your_telegram_chat_id
FINMIND_TOKEN=
```

`API_KEY` / `SECRET_KEY` 只有在期交所日 K 缺日、需要 Shioaji 補近月時才會用到。沒有金鑰時會記錄警告，不會用 `assert` 中斷，也不會改拿 `TXFR1`。

`TG_TOKEN` / `TG_CHAT_ID` 缺一就只存日誌、不推播。有設定時以 Telegram Markdown 發送；解析失敗會再試一次純文字。動態文字裡的底線、星號、反引號與左方括號會跳脫，整則說明也會收在 1024 字以內。

`FINMIND_TOKEN` 可留空。最後結算價的 FinMind 備援需要 Backer 以上。

Shioaji 登入使用 `simulation=True`。登入與 K 棒請求會重試 3 次，K 棒逾時 30 秒，並且每段最多 30 天（單次查詢上限）。

## 執行

在專案目錄：

```bash
# 最近 8 個結算日，黃線只計日盤
python settlement.py

# 最近 5 個結算日
python settlement.py 5

# 黃線納入夜盤
python settlement.py 8 --include-night
```

`N` 必須是 1 到 120 的整數。`0`、負數或非數字會結束並留下錯誤訊息，不會拋出未處理的例外。

## 已知限制

- 沒有在有 Shioaji 憑證與 Telegram 的環境重跑整條推播，補資料與發送是否成功要看當次日誌。
- 期交所每日行情單次大約只能抓 30 天，程式會分段；網站改版或回傳網頁時，該段會失敗並嘗試用 Shioaji 補**尚未到期**的月份。
- 已到期月份若期交所失敗，Shioaji 補不回來。
- 黃線不是逐筆 VWAP。夜盤的日期採用期交所日報：某一交易日的「盤後」是前一晚 15:00 到清晨 05:00。
- 內建交易日曆只到 2026-12-31。之後若 FinMind 也連不上，假日可能沒被排除。
- 政府資料開放平臺的最後結算價檔更新頻率是年，而且目前不是完整歷史，所以沒有拿來當來源。
